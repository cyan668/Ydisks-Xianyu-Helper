## 数量策略契约

在自动化规则的每条“卡密库存/发货模板”内容上选择：

- **按购买数量**（`per_item`）：实际取卡份数 = 购买件数 × 配置份数。字段省略时保持此历史行为。
- **每单固定份数**（`per_order`）：实际取卡份数 = 配置份数，不乘购买件数。

策略存入该动作 `config_json.quantity_mode`，随运行 `ActionPlan` 冻结，无数据库迁移。
模板动作的策略作用于各变量绑定的 `delivery_count`，不再叠乘模板动作外层份数；模板凭证仍以实际消息条数计量。
未知策略在保存及匹配动作执行时拒绝；历史补发按原计划计算，不读取现行规则替换历史义务。
列表中的坏配置按动作显示告警，不阻断其它规则；未知策略必须明确重选，损坏 JSON 不会被静默覆盖。
不放宽付款事实、金额、购买数量、SKU、幂等、未知结果或库存恢复门禁；不新增 MTOP 请求。

商品模板库/批量发布原入口仍按既有默认生成规则；需要固定份数时，在生成后的自动化规则页设置。
它们与已有规则编辑不是同一对象，不能借本次改动自动重写既有模板或线上规则。

## 黑名单保护契约

交易黑名单按当前用户隔离，支持用户全部账号、单个账号、单个账号的指定商品；只按稳定买家 ID 匹配，兼容 `@goofish` 后缀，昵称仅作管理展示。商品级优先于账号级，再到用户级；停用条目不参与匹配。手工新建默认停用，订单页明确确认后的拉黑记录启用；关单另有独立开关。它不代替平台会话拉黑，也不自动关闭普通关键词/AI 客服回复。

### 个人名单管理与原系统迁移

支持按账号、买家 ID/昵称/原因搜索和数据库分页。选择只覆盖当前页；批量启用、停用和删除只作用于明确选中的记录，混入不存在或其他用户的记录时整批拒绝。导出本人账号筛选下的完整 CSV，不限当前页，带 UTF-8 BOM 和公式前缀防护，不清空未保存的编辑草稿。

可导入 Auto Replay 的 XLSX，也支持 CSV/TSV；表头兼容 `账号ID,买家ID,买家昵称,商品ID,拉黑原因,是否启用`。一次最多 500 条，先验证整份文件，再原子提交；同用户/买家/账号/商品四元组重复时跳过，保留旧配置，不覆盖。启用列接受原系统的“是/否”及明确布尔格式，缺省停用；关单列缺省关闭，未知值拒绝，账号与商品必须属于当前用户。买家长 ID 始终按文本处理。

订单详情中的“一键拉黑”必须明确选择商品、账号或用户范围，由服务端从拥有的订单派生买家身份，创建启用但不关单的本地规则；重复添加只反馈跳过，不立即关单，也不调用官方拉黑。

### 官方黑名单以当前会话为操作单位

聊天页独立提供官方会话状态查询、拉黑和解除。打开面板不请求平台；只有手动查询得到明确状态后才显示相应写操作，写前再次确认。每次操作至多一次平台请求，经过既有账号节流，不刷新 Token、不自动重试或后台轮询；结果未知时清除旧状态，提示手动查询。会话/账号切换会丢弃旧响应。先检查本地会话归属，再读取最小凭据快照；空凭据不发请求，响应 Cookie 沿用已有条件写回且锁外更新运行时。

源系统固定快照的“闲鱼黑名单”页只读取本地 `XYPlatformBlacklist`，没有可验证的全量同步写入链；当前源页面名单为空，也只有刷新。已核实的官方接口仅按 `sessionId` 查询/新增/解除，不能据此实现全量同步。因此不把本地刷新标为同步，不添加虚假同步按钮。个人交易名单与官方会话名单独立维护。

依据：[源个人名单导入导出](https://github.com/zhinianboke/xianyu-auto-reply/blob/a58dea0d8ef43d4f467f09b5607af4821710700a/backend-web/app/api/routes/blacklist.py#L147-L264)、[订单范围确认](https://github.com/zhinianboke/xianyu-auto-reply/blob/a58dea0d8ef43d4f467f09b5607af4821710700a/frontend/src/pages/orders/BlacklistLevelModal.tsx#L36-L117)、[官方会话协议](https://github.com/zhinianboke/xianyu-auto-reply/blob/a58dea0d8ef43d4f467f09b5607af4821710700a/backend-web/app/services/chat_new/official_blacklist_service.py#L13-L57)。

自动发货、赠品、模板、API 卡取卡、逐份库存、快照补发、人工完整发货和“仅确认发货”均核验实时黑名单；查询失败或相关规则存在但身份缺失时停止。没有配置黑名单的旧调用保留原订单事实合同。

仅经过既有卖家核验、账号启用和暂停门禁的 WS 拍下/付款系统事件，才允许尝试自动关单；调度恢复和人工补发只拦截，不发起关单。关单还要求本地同账号订单身份一致且仍为待付款/待发货，已有运行、发送内容或不确定结果时不提交。保持原砍价免拼与付款发卡阶段顺序，不改变冻结验证码或认证恢复。

每个账号/订单请求前持久化唯一占用，最多一次 MTOP 请求，沿用统一账号级节流；不新增扫描、并发、Token 刷新或自动重试。明确成功后原子收口本地关闭状态；超时、错误响应或保存失败保留阻断并发送独立人工处理通知。重复事件、重启、删除或停用规则都不能解除未知关单结果保护；需要在平台人工核对并处理该交易，不自动继续发货。

协议事实来自源项目固定快照的 [个人黑名单匹配](https://github.com/zhinianboke/xianyu-auto-reply/blob/a58dea0d8ef43d4f467f09b5607af4821710700a/websocket/app/services/xianyu/delivery_rules/personal_blacklist_rule.py#L90-L167) 与 [Cookie 卖家关单实现](https://github.com/zhinianboke/xianyu-auto-reply/blob/a58dea0d8ef43d4f467f09b5607af4821710700a/websocket/app/services/xianyu/auto_delivery_handler.py#L3674-L3808)。不使用需要 ISV accessToken 的另一套关单接口，也不复制源项目连续重试策略。

三方言迁移 `00059_buyer_blocks` 保存配置和关单占用，`00060_buyer_block_management` 增加管理展示昵称。两项原按叠加 PR 开发，现已先合并数量策略，再将黑名单基线转到 `codex/custom` 并合并。真实个人名单仅导入隔离的本地验收库，不上传公开 Fork，不更新线上 ydisks 数据；未调用真实平台拉黑、解除或订单关单接口，线上部署和账号仍保持原状态。

## 人工接管暂停契约

2026-10-31：按用户“逐项开始做”的授权，数量策略 PR #1 以合并提交 `73fa22d` 进入定制分支，黑名单 PR #2 调整基线后以 `1d28a0f` 合并；人工接管在 `codex/manual-takeover-pause` 开发。线上数据、镜像和账号启停尚未改变。

规则页“回复保护”按账号设置人工回复后的暂停分钟数，范围 0–1440；旧账号默认 0，保存正数不立即开始暂停。源账号实际使用 10 分钟，可在配置迁移时明确设置。该设置独立于原账号订单任务的 `pause_duration/paused_until`，只拦截 API、关键词、AI、默认回复和商品首次回复，订单事件、自动发货和人工聊天保留原合同。

本程序人工文字、图片和商品卡片成功发送后建立会话接管；结果不确定时仍保护会话，明确未发送的失败不触发。自动客服共用发送管线时携带内部来源；自动发货沿用既有自动确认标记，不被当成人工。每个本地发送在 WebSocket 写入前登记来源，严格响应中的 mid/PNM 绑定用于识别回显；缓存仅保留有界正文摘要和非敏感标识，不持锁进行外部 I/O，不更改原自动化投递确认器。

跨端暂停只接受当前账号实例启动后、一分钟内的实时自身消息，并要求稳定平台键和实际发送时间。与未确认本地请求同文、缺少时间、来源记录容量淘汰期间或旧同步回放时保留来源不确定，不猜测为人工，也不延长十分钟窗口。已经持久化的接管在重启后继续生效。

截止时间从人工消息实际发送时间计算；同一消息的本地观察和平台回显使用稳定关联键去重。新人工消息可以延长窗口，重复回放不能延长。到期仅开放后续正常回复，不新增消息补发队列。生成前及投递前核验最新状态，图片上传后再次核验；旧生成请求保留买家消息接纳水位，即使用户主动恢复，也不会补发人工接管以前生成中的旧回复。已进入平台发送的消息无法由本地暂停撤回。

聊天会话提供接管状态和明确恢复入口。恢复使用同一快照的递增版本比较更新，防止两条人工消息拥有相同截止时间时，旧页面清除新的接管。恢复保留去重账本；关闭账号接管配置则结束该账号已有会话暂停。状态与设置接口只访问本地数据库，核验账号及可见会话归属，不读取 Cookie，不新增 MTOP 请求或后台平台轮询。
